## 1. บทบาทและสิทธิ์ในระบบ (Role-Based Access Control)
ระบบ NewTEA กำหนดสิทธิ์การใช้งานออกเป็น 5 บทบาทหลัก:
| บทบาท (Role) | สิทธิ์การเข้าถึงและการทำงาน |
| :--- | :--- |
| **`ADMIN`** (ผู้ดูแลระบบ) | สิทธิ์สากลสูงสุด (Universal Bypass): จัดการผู้ใช้ทั้งหมด, นำเข้านักเรียน, จัดการครูที่ปรึกษา, ตั้งค่าเกณฑ์คะแนน, แก้ไขหรือปลดล็อกวิชาใดก็ได้ในระบบ |
| **`ACADEMIC`** (ฝ่ายวิชาการ) | เข้าถึงแดชบอร์ดติดตามภาพรวมทั้งโรงเรียน (`/academic`), ตรวจอนุมัติคะแนนระยะที่ 1–3, บันทึกการส่งคะแนนเข้า SGS, อนุมัติคำขอปลดล็อกคะแนน |
| **`DEPT_HEAD`** (หัวหน้ากลุ่มสาระฯ) | เข้าถึงแดชบอร์ดกลุ่มสาระฯ ตนเอง (`/dept-head`), ตรวจรับรองคะแนน (APPROVED / REVISE), พิจารณาคำขอปลดล็อกคะแนนของครูในกลุ่มสาระฯ |
| **`TEACHER`** (ครูผู้สอน) | สร้างรายวิชา, เชิญครูร่วมสอน, บันทึกเวลาเรียนและคะแนนเฉพาะห้องที่รับผิดชอบ, ส่งตรวจ 3 ระยะ, ขอปลดล็อกคะแนน, คัดลอกเข้า AutoSGS, พิมพ์ ปพ.5 |
| **`ADVISOR`** (ครูที่ปรึกษา) | เข้าถึงแดชบอร์ดเฉพาะห้องตนเอง (`/advisor`) ดูสถิติผลการเรียน, ติดตาม นร. ติด 0/ร/มส, ตรวจสอบรายชื่อกลุ่มภาษาและวิชาเลือก |

## 2. การจัดการบัญชีผู้ใช้งาน (User Management)
ไปที่เมนู **"จัดการผู้ใช้" (`/admin/users`)**:
1. **การเพิ่ม/แก้ไขผู้ใช้รายบุคคล:** สามารถกรอกชื่อ นามสกุล อีเมล กลุ่มสาระฯ และกำหนดบทบาท (Role)
2. **การรีเซ็ตรหัสผ่าน:** แอดมินสามารถกดปุ่ม "รีเซ็ตรหัสผ่าน" เพื่อกำหนดรหัสผ่านใหม่ให้ครูได้ทันที โดยระบบจะเข้ารหัสด้วยอัลกอริทึม Scrypt ตามมาตรฐานความปลอดภัยของ Better Auth
3. **การนำเข้าผ่าน Excel / CSV (Batch Import):**
   - กดปุ่ม **"ดาวน์โหลด Template"** เพื่อดูรูปแบบคอลัมน์มาตรฐาน (`Email`, `Name`, `Role`, `Department`, `Password`)
   - อัปโหลดไฟล์เพื่อสร้างหรืออัปเดตข้อมูลผู้ใช้ทั้งโรงเรียนในคราวเดียว
4. **ความปลอดภัย:** ระบบมีระบบป้องกันไม่อนุญาตให้ลบผู้ดูแลระบบ (ADMIN) คนสุดท้ายของระบบ

## 3. การนำเข้าข้อมูลนักเรียนและครูที่ปรึกษา (Student & Advisor Import)
### 3.1 ข้อมูลนักเรียน 45 ห้อง (`/admin/students`)
1. อัปโหลดไฟล์ Excel/CSV ข้อมูลนักเรียน โดยระบบจะตรวจจับคอลัมน์: รหัสประจำตัว, บัตรประชาชน, คำนำหน้า, ชื่อ, นามสกุล, ห้อง (`4.1` - `6.15`), เลขที่, ภาษาที่ 3, วิชาเลือก
2. **การย้ายห้องและเปลี่ยนสถานะ:** แอดมินสามารถปรับสถานะนักเรียนเป็น `ACTIVE`, `TRANSFERRED`, หรือ `RESIGNED` โดยระบบจะบันทึกประวัติย้อนหลัง (Audit Log) เสมอ และคะแนนในวิชาเดิมจะไม่สูญหาย

### 3.2 ครูที่ปรึกษาประจำ 45 ห้อง (`/admin/advisors`)
1. กำหนดครูที่ปรึกษา 1–3 ท่านต่อห้องเรียนตามโครงสร้างของโรงเรียนเตรียมอุดมศึกษาภาคเหนือ
2. มีระบบค้นหาและแนะนำชื่อครูอัตโนมัติ (Datalist Autocomplete)
3. ข้อมูลครูที่ปรึกษาจะถูกส่งต่อไปแสดงในหน้าปก ปพ.5 ของทุกวิชาโดยอัตโนมัติ

## 4. การตั้งค่าปีการศึกษาและกำหนดการส่งตรวจ 3 ระยะ (Terms & Milestones)
ไปที่เมนู **"ภาคเรียนและกำหนดการ" (`/admin/terms`)**:
1. กำหนดปีการศึกษาและภาคเรียนที่เปิดใช้งาน เช่น 2568 ภาคเรียนที่ 1
2. กำหนดวันครบกำหนด (Deadline) การส่งตรวจทั้ง 3 ระยะ:
   - ระยะที่ 1: ตรวจคะแนนก่อนกลางภาค
   - ระยะที่ 2: ตรวจคะแนนสอบกลางภาค
   - ระยะที่ 3: ตรวจคะแนนปลายภาค และโอนเข้า SGS

## 5. การตั้งค่าเกณฑ์การประเมิน 3 ด้าน (Assessment Criteria Settings)
ไปที่เมนู **"ตั้งค่าเกณฑ์ประเมิน" (`/admin/settings`)**:
- ปรับแต่งเกณฑ์คะแนน Auto-map สำหรับคุณลักษณะอันพึงประสงค์, การอ่านคิดวิเคราะห์และเขียน, และสมรรถนะสำคัญ
- กำหนดสัดส่วนคะแนนมาตรฐานที่แปลงเป็นระดับ 3 (ดีเยี่ยม), 2 (ดี), 1 (ผ่าน), 0 (ไม่ผ่าน)

## 6. แดชบอร์ดติดตามความก้าวหน้าฝ่ายวิชาการ (Academic Overview Grid)
ไปที่เมนู **"ติดตามภาพรวมวิชาการ" (`/academic`)**:
- แสดงตารางรวมวิชาทั้งหมดในโรงเรียน (รหัสวิชา, ชื่อวิชา, ครูผู้สอน, ห้องที่สอน)
- ไฟสถานะความก้าวหน้าแบบเรียลไทม์ (TEA68 Grid):
  - 🟢 **สีเขียว:** ส่งตรวจและอนุมัติเรียบร้อยแล้ว
  - 🟡 **สีเหลือง:** รอการตรวจรับรอง
  - 🔴 **สีแดง:** ส่งกลับให้ครูแก้ไข
- ปุ่ม **"โอนคะแนนเข้า SGS"** สำหรับฝ่ายวิชาการเพื่อทำเครื่องหมายว่าวิชานี้บันทึกเข้าระบบ สพฐ. เรียบร้อยแล้ว

## 7. การตรวจรับรองและการอนุมัติปลดล็อกคะแนน (Verification & Unlock Approvals)
1. **การตรวจรับรองปกติ:** หัวหน้ากลุ่มสาระฯ (`/dept-head`) และฝ่ายวิชาการ (`/academic`) สามารถคลิกดูสมุดคะแนนและกด **"อนุมัติ"** หรือ **"ส่งกลับแก้ไข"** พร้อมพิมพ์คอมเมนต์กำกับ
2. **การอนุมัติปลดล็อก (Unlock Requests):** เมื่อครูส่งคำขอแก้ไขคะแนนเข้ามา จะแสดงการแจ้งเตือนพร้อมเหตุผล
   - ระบบมี **SGS Protection Guard**: หากวิชานั้นโอนเข้า SGS ปลายภาคแล้ว ระบบจะแสดงข้อความเตือนพิเศษก่อนอนุมัติปลดล็อก
   - มีการบันทึกประวัติ (Audit Trail) ว่าใครเป็นผู้อนุมัติปลดล็อก วันและเวลาที่อนุมัติอย่างชัดเจน

## 8. คู่มือสถาปัตยกรรมและการบำรุงรักษาเซิร์ฟเวอร์ (DevOps & Server Maintenance)
> 📖 **คู่มือติดตั้งและ Re-deploy ละเอียดเฉพาะระบบ NewTEA:** อ่านขั้นตอนฉบับเต็มได้ที่ [docs/DEPLOYMENT_NEWTEA.md](file:///D:/TUNorth/apps/NewTEA/docs/DEPLOYMENT_NEWTEA.md)

NewTEA รันบน **Ubuntu Server 24.04 LTS** ผ่าน Docker Container บนเครือข่ายภายใน `tunorth-net`:

| บริการ (Service) | Container Name | Port ภายใน | การเชื่อมโยงภายนอก |
| :--- | :--- | :--- | :--- |
| **Frontend** | `tea-frontend` | `3000` | Nginx Port `8010` / `tea.tn.ac.th` |
| **Backend API** | `tea-backend` | `8080` | Reverse Proxy `/api/` |
| **Database** | `tea-db` | `5432` | DB: `tunorth-tea_db` (จัดการที่ `infra/docker-compose.yml`) |

### บัญชีผู้ดูแลระบบเริ่มต้น (Default Superadmin Account):
เมื่อเริ่มต้นระบบบนฐานข้อมูลว่างเปล่า (Fresh DB) ระบบจะสร้างบัญชีเริ่มต้นให้อัตโนมัติ:
- **อีเมล:** `admin@tn.ac.th`
- **รหัสผ่านเริ่มต้น:** `Admin@2026`
- **สิทธิ์:** `ADMIN` (เข้ารหัสด้วย Scrypt ถูกต้องตามมาตรฐาน Better Auth)
*(หมายเหตุ: แนะนำให้เปลี่ยนรหัสผ่านทันทีหลังเข้าสู่ระบบครั้งแรกเพื่อความปลอดภัย)*

### คำสั่งสำหรับดูแลระบบ (Operations Commands):
```bash
# 1. ติดตั้งหรือ Re-deploy ระบบ NewTEA แบบด่วน (Single App Deploy)
~/TUNorth/scripts/deploy_newtea.sh

# 2. หรือ Re-deploy ผ่านคำสั่งมาตรฐาน
cd ~/TUNorth/apps/NewTEA
docker compose up -d --build

# 3. ตรวจสอบสถานะ Containers
docker ps --filter "name=tea"

# 4. ดู Logs การทำงานแบบ Real-time
docker logs -f tea-backend
docker logs -f tea-frontend

# 5. สั่ง Backup ฐานข้อมูล NewTEA ทันที
~/TUNorth/scripts/backup.sh

# 6. กู้คืนฐานข้อมูล NewTEA (Smart Restore)
~/TUNorth/scripts/restore_db.sh latest tea
```
*(ระบบมีการสำรองข้อมูลอัตโนมัติทุกวันในเวลา 02:00 น. จัดเก็บที่ `~/TUNorth/backups/`)*
